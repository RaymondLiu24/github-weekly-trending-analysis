## 個人精選

### [TencentCloud/Octop](https://github.com/TencentCloud/Octop) 🧠（本週排名：25）

- **它在做什麼：** 自架的 AI 助理平台，支援多使用者與多 agent，同一套系統提供 web dashboard、CLI 與訊息平台接入，資料留在本機。內建「portable memory」（harness-memory，支援 hierarchical recall 與 full-text search）和可做 semantic retrieval 的 RAG 知識庫；agent 的 memory 綁在 workspace 上，會隨 workspace 一起遷移。
- **跟我的方向有什麼關係：** 本週 Top 30 裡最貼近個人 AI 助理的一個：memory、RAG 知識庫、本機資料、多 agent 都在同一個 repo 裡，可以直接拿來對照 super project 的記憶層設計。
- **值得注意的技術選擇：** Python 3.12+、FastAPI／uvicorn，單一 process 同時跑 harness-agent runtime 與負責 IM channels 的 harness-gateway，狀態存 SQLite（可換 PostgreSQL），部署門檻低。memory 做成隨 workspace 移動的資產，是值得學的設計。另有 16 個 persona 模板（含 MBTI 風格）。版本 v1.0.1、4.4k stars，仍屬早期。

### [Tencent/WeKnora](https://github.com/Tencent/WeKnora) 📚 🧠（本週排名：30）

- **它在做什麼：** 開源 LLM 知識平台，把原始文件轉成可查詢的知識系統，核心有三塊：RAG Q&A、串接檢索與工具的 ReAct agent，以及 Wiki Mode（agent 自動產生結構化 markdown 知識庫，附 revision history）。
- **跟我的方向有什麼關係：** Wiki Mode 和上週個人精選的 nashsu/llm_wiki 走同一條路：讓 LLM 持續維護一份有結構、可回溯的 wiki，而不是每次重新檢索。另有 cross-session long-term memory，對應個人助理的記憶需求。不過它偏企業向（workspace RBAC、scoped API keys），個人使用會偏重。
- **值得注意的技術選擇：** 向量庫可插拔（PostgreSQL/pgvector、Elasticsearch、Milvus、Qdrant），LLM provider 也可換（OpenAI、DeepSeek、Claude 等）；skill 跑在 Docker／E2B／Cube sandbox；用 Langfuse 做 observability。v0.8.0 新增 session 持久化的 skill sandbox 與 cross-session memory 管理。（推論：個人規模只需 pgvector 一種即可，不必上 Milvus 之類。）

### [docling-project/docling](https://github.com/docling-project/docling) 🧠 📚（本週排名：27）

- **它在做什麼：** 文件解析工具，輸入支援 PDF、DOCX、PPTX、XLSX、HTML、EPUB、圖片、音訊、影片、email，輸出 Markdown、JSON、HTML 等結構化格式。PDF 理解靠 GraniteDocling 這類 visual language model，掃描件走 OCR，音訊與影片走 ASR。
- **跟我的方向有什麼關係：** 這是把日記、履歷、PDF 等個人資料餵進 RAG 或知識庫之前的前處理層。支援本機執行，處理敏感個人資料時不必送出雲端；也已整合 LangChain、LlamaIndex、Crew AI。
- **值得注意的技術選擇：** 跨十種輸入格式的統一解析，加上 VLM、OCR、ASR 三條模型路線，並保留本機執行選項。起源於 IBM Research，現由 LF AI & Data Foundation 託管。

### [paperless-ngx/paperless-ngx](https://github.com/paperless-ngx/paperless-ngx) 📚（本週排名：19）

- **它在做什麼：** 社群維護的文件管理系統，把紙本與掃描文件變成可搜尋的數位檔案庫，靠 OCR、full-text search 與機器學習自動標籤。
- **跟我的方向有什麼關係：** 屬 PKM 的 capture 與封存層，適合當個人文件的來源庫。它偏文件封存與檢索，不做知識連結或 LLM 問答，頁面上也沒看到 AI／LLM 功能，所以只算邊緣的 📚。
- **值得注意的技術選擇：** Django + Angular，OCR、full-text search、ML 標籤的組合，走成熟的「先讓文件可被搜尋」路線；45.7k stars，是官方認定的 Paperless 與 Paperless-ng 的後繼專案，官方 demo 在 demo.paperless-ngx.com。

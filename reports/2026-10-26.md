## 個人精選

### [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) 📚（本週排名：15）

- **它在做什麼：** 把 codebase 連同文件、SQL schema、設定檔、PDF 轉成可查詢的 knowledge graph，以 `/graphify` skill 裝進 Claude Code、Cursor、Codex、Gemini CLI。程式碼用 tree-sitter 在本機解析，文件則交給助理的模型或另設的 API key 處理；圖、音訊與影片也會進同一張圖。
- **跟我的方向有什麼關係：** 這是把「一堆文件」變成「可以問問題的結構」的現成做法，跟第二大腦的知識庫層直接相關。頁面沒有特別提到 Markdown 或 Obsidian，要拿來處理個人筆記得自己試。
- **值得注意的技術選擇：** 不用 vector store 也不用 embeddings，查詢直接跑在本機的 `graph.json` 上（`query`、`path`、`explain`），再用 Leiden clustering 分群，並提供可選的 MCP stdio server。這跟主流 RAG 走的是相反方向，值得拿來跟 embedding 式檢索比較。135.5k stars，本週 5 天上 Trending。

### [ruvnet/ruflo](https://github.com/ruvnet/ruflo) 🧠（本週排名：22）

- **它在做什麼：** 多 agent swarm 的 harness，整合 Claude Code 與 Codex，涵蓋 agent teams、learning loop、安全控制與 persistent memory。
- **跟我的方向有什麼關係：** 主體是 agent 編排，不是個人助理，但記憶是它四大核心能力之一，架構上有一層「Memory & Learning」夾在 agent 與 LLM provider 之間，可以參考記憶層該放在哪裡。
- **值得注意的技術選擇：** 記憶存在 AgentDB（vector DB），用 HNSW 索引，README 自報 2 萬筆時比 brute force 快約 1.9 倍、recall@10 接近 0.99；RAG plugin 另加 hybrid search 與 graph hop；跨 session 記憶由 ruflo-rvf plugin 存取與還原。

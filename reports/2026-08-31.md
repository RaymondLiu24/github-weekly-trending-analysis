## 個人精選

### [AgriciDaniel/claude-obsidian](https://github.com/AgriciDaniel/claude-obsidian) 📚（本週排名：16）

- **它在做什麼：** 由 15 個 Claude Code skills 組成的知識管理系統，把使用者丟進來的來源資料經 Claude 整理成有引用、可連結的 Markdown 筆記，寫入一般的 Obsidian vault（非隱藏在外掛快取或雲端資料庫），並用 claim／source 雙帳本追蹤每則主張的可信度與新鮮度。
- **跟我的方向有什麼關係：** 這正是 PKM 與 agent memory 交界處的核心設計——vault 保持純 Markdown、可用 grep 或 Obsidian 直接開啟，檢索預設走本地 BM25，只在明確授權時才呼叫 embedding／remote rerank；「先求可攜與透明，再談語意搜尋」的取捨，與 8/24 週報精選的 akitaonrails/ai-memory 呼應，是同一條「輕量、可審查、本地優先」設計脈絡的延伸案例。
- **值得注意的技術選擇：** 五步驟交易安全機制（讀取雜湊 → 草稿彙整 → 合併 → 人工核可 → 原子套用）確保每次 mutation 都可回復；系統明確聲明「不支援 PDF 語意抽取、不做即時網頁索引」，寧可「有根據地拒絕」也不捏造引用——這種誠實劃出能力邊界的態度，對設計可信賴的個人知識庫是很值得參考的原則。

### [tinyhumansai/openhuman](https://github.com/tinyhumansai/openhuman) 🧠（本週排名：21）

- **它在做什麼：** 定位為「個人 AI 超級智慧」的開源 agent 框架，核心是「Memory Tree」架構——透過 100+ OAuth 整合與 5,000+ MCP servers 持續拉取 Gmail、Notion、GitHub、Slack 等資料，用自研 TokenJuice 壓縮技術（號稱省下最多 80% token）壓縮後存進本機 SQLite，並轉譯成 Obsidian 相容的 Markdown 知識庫。
- **跟我的方向有什麼關係：** 「持續、跨管道、壓縮後的長期記憶」正是個人 AI 助理最終要解決的問題——不像一般聊天機器人記憶侷限在單一對話視窗，它把使用者的數位生活整個攝入並壓縮成可負擔的上下文；17 個訊息管道（Telegram、iMessage、email 等）的多入口設計，也示範了「助理無所不在」而非「困在單一 App」的產品思路。
- **值得注意的技術選擇：** Rust 核心搭配 checkpointed graph（而非單純 linear loop）執行 agent，讓長流程可以中途暫停等待人工核可、也能斷點恢復；「Privacy Mode」在 Rust 層強制本地推理、TokenJuice 壓縮換取成本可控，是個人記憶系統在「隱私—成本—能力」三角取捨中的具體示範。
